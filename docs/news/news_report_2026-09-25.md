#### [tip] GitHub Security Lab 发布 LLM 驱动的 Fuzzing Taskflow，自动完成 C/C++ 项目模糊测试全流程
- **来源**: GitHub Blog · 2026-09-24
- **相关度**: 7/10 | 案例价值: MEDIUM
- **链接**: [https://github.blog/security/application-security/ai-powered-fuzzing-with-the-github-security-lab-taskflow-agent](https://github.blog/security/application-security/ai-powered-fuzzing-with-the-github-security-lab-taskflow-agent)
- **事件摘要**: GitHub Security Lab 的 Antonio Morales 开源基于 Taskflow Agent 的 Fuzzing Taskflow：用户只需给出 owner/repo，流水线即自动识别入口点、分析构建系统、编写 harness、运行 AFL++、读取覆盖率报告、改进 harness、分诊每个崩溃并为每个唯一漏洞生成报告。设计原则是明确分离「代理拥有决策权、MCP 工具拥有执行权」——代理从不直接调用 AFL 或 clang，只组合 run_afl_for、compile_harness 等原语，状态仅经 SQLite 传递。覆盖率循环按 30 秒起倍增时间预算至 960 秒，连续两轮增益低于 1% 即判平台期停止；每个 harness 构建两个二进制（afl-clang-lto 供模糊测试、clang 插桩供可读覆盖率报告）；支持结构感知变异（JSON/XML/regex 定制变异器、源码常量字典、语料拼接）；语料库跨迭代与跨活动持久化。默认模型 Claude Sonnet 5。作者明确警告：流水线在主机上直接运行 AFL、clang 与 LLM 选择的任意构建命令，无容器隔离，被提示注入的代理原则上可执行用户能做的一切，只能在一次性环境运行；建议补丁一律标注「需要审查」。
- **理论关联**: 碳硅共生（Ch5 SIII）的正面对照：把 fuzzing 中编写 harness、读覆盖率、追缺口、分诊崩溃的重复劳动交给代理，人类保留判断与审查，与 9/20 Trail of Bits、9/18 Anthropic 开源生物分子模型构成「验证能力被增强而非让出」的坐标。但「代理判断/工具执行」的分离同时把对齐风险前移到宿主权限层——提示注入即等价任意代码执行，是暗时间架构自带的攻击面。
