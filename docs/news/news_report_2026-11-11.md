### 6. Claude Code 被曝把密码写进项目文件，GitHub 上发现 2539 个真实凭据，官方正在修复

- **相关度**: 8/10 | 案例价值: HIGH
- **紧迫度**: immediate | 更新类型: case_study

- **事件摘要**: 2026 年 11 月 10 日，IT之家转述 Ars Technica 与安全公司 Apiiro 的发现：超过 10 万份 Claude Code 本地设置文件被上传到公开 GitHub 仓库，其中约 1100 份含有数据库密码、API Token、私钥或 root 登录信息；结合 Git 历史、共享设置文件与智能体聊天记录，共在 1994 个代码库中识别出 2539 个真实凭据，波及 63 个组织，包括学生团队、初创公司、软件代理商与成熟供应商，泄露内容包括 Azure 数据库密码、Square 生产令牌、SSH root 登录信息乃至医疗记录数据库的拥有者密码。机制在于 Claude Code 处理「自动执行命令」授权的方式：用户在询问是否允许某条 Shell 命令时选择「是，且不再询问」，该规则连同命令原文——可能夹带密码、令牌、密钥——一并写入 .claude/settings.local.json；该文件本应被全局 .gitignore 排除，但当项目被克隆到另一台机器、或普通文件夹后来才初始化为 Git 仓库时，就可能被误提交。研究还称 Claude Code 有时会在未经确认的情况下自行提交设置文件变更，且即便原仓库删除，fork 仍会留存密钥。统计上允许列表越大风险越高：超过 8KB 的文件每十个有一个含真秘密，小于 500 字节的文件不到五百分之一。同类 bug 早在 2025 年 8 月已被报告，因 60 天无活动被关闭；Claude Code 团队的 Boris Cherny 于 11 月 7 日回应称正在研究预防措施，并考虑内置密钥扫描。
- **理论关联**: 支持「需求侧规训」的代价结构：每一次「不再询问」都是用未来的安全边界换取当下的摩擦消除，而摩擦正是判断发生的位置。这同时补足「暗时间」的一条：授权决策被写入文件后不再被任何人重读，审计对象从「人」变成「配置」——没有人在场，所以没有人负责。
