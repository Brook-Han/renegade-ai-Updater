- **事件摘要**: Codex 让工程师并行改动数量远超以往，每次 push 又触发多个 CI 作业重复 fetch 同一 commit，OpenAI monorepo 的 Git 服务可靠性一度跌破 90%，2025 年底起出现 fetch/push 缓慢与 merge 失败。OpenAI 遂重建 Git 后端 Pando：与 Git 协议和客户端完全兼容，核心设计由 1 名工程师完成、Agent 团队实现、少数工程师部署，10 周上生产，2026 年 4 月起承载流量，迁移数百个集成与数百万分支。中位 push 延迟降近 80%，每日交付近 1PB Git 数据，单小时峰值 57TB+ pack、其中 99% 以上来自缓存，仅少量 CPU 核心即可支撑；push 元数据 O(1)、fetch O(log Δ)。它放弃全仓库时点一致性、改为因果一致性，只对单个 ref 串行化，理由是用户与 Agent 都不关心 ref 的全局顺序。另用 GPT-6 Astra 让 Agent 写 Lean 与 TLA+ 形式化「Pando 理论」并证明性质，连续会话数百小时找边界 bug。

- **事件摘要**: 腾讯混元 11-02 发布 AI 科研系统 Hyra 2.0，把重点从「用 AI 直接解题」转向「让通用 Agent 参与研发科学模型、研究工作流与软件工具」，使一次研发成果可在后续任务中反复使用，官方称之为从「刷题解题」走向「造工具」、形成「智能复利」。架构分三层：Overall 与人类研究者沟通并对齐目标，Mission 长期负责单一研究问题并判断路线取舍，Worker 独立读代码、做实验、分析失败原因，并可质疑 Mission 的判断。系统另设三套分离存储：项目状态、Agent 分层记忆、共享知识库 Books；项目复盘时可把可迁移方法整理成 skill 供后续任务直接调用。此前 Hyra 1.0 曾驱动开源模型解决加法组合学中悬置五十余年的开放问题。
- **理论关联**: 丰裕闭环的工程形态。关键不在解题而在把解法沉淀为可复用工具，于是单次投入的收益随任务数摊薄——这与「每次从零推理」的调用式 AI 是两种经济结构。Worker 可质疑 Mission 这一设计尤其值得记：层级里内置了向上反驳的通道，是对「对齐即服从」的一次结构性偏离。
