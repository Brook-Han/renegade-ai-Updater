### 2. Google 强制 AI Agent 走 Workspace MCP 服务器，Gmail 服务器不能发邮件

- **相关度**: 9/10 | 案例价值: HIGH
- **紧迫度**: immediate | 更新类型: new_evidence

- **链接**: [https://techstackups.com/articles/google-workspace-ai-agents-mcp/](https://techstackups.com/articles/google-workspace-ai-agents-mcp/)
- **事件摘要**: 11 月 24 日 Google 将八个 Workspace MCP 服务器正式开放，并在 API 条款中新增《Workspace AI 工具附录》：自 2027 年 2 月 1 日起，任何「本身是或由 AI Agent 驱动」的工具必须经由这些服务器访问 Gmail、Drive、Calendar 等；直接调用 REST 的 agent 一律按 Standard 级配额处理（每项目每产品每天 5,000 次，一次 search_threads 计 10 次，即全天约 500 次搜索），无论付费等级。公开的 Gmail 服务器只能搜索、读取、建草稿、打标签，不能发送、回复、转发或修改草稿，这些工具标注「需合作伙伴权限」；Drive 同样不能移动、改名、共享。Anthropic 的 Workspace 连接器恰好提供发送与移动，形成「大厂可发信、独立开发者只能留草稿」的落差。附录另设数据条款：Workspace 数据仅可用于用户授权任务，断开即删；「Google 技术信息」保留上限 30 天，定义涵盖向量嵌入、记忆索引、用户画像与组织图谱；禁止训练、微调、评测与蒸馏。
- **理论关联**: 支持「共识牢笼」与「资本驯化」的合流：准入不再靠封禁，而靠协议。把「谁是 agent」写进 OAuth 勾选框、把「能做什么」写进合作伙伴名单、把「能记多久」写进 30 天上限——三层都由平台单方面定义，且每一层都以安全为名。对「暗时间」是更硬的一刀：记忆索引 30 天必须重建，意味着 agent 的连续性变成按月的订阅品，长期理解被制度性地禁止积累。

- **事件摘要**: 支付宝 2026 年 7 月上线的 Skill 交易平台 SkillPay，提供买断与订阅两种售卖模式，作者实测完整流程。买断制定价 0.01–50 元，付款后 Skill 完整内容交付到本地，可在 WorkBuddy、豆包、Codex、Claude Code 等任意 Agent 中调用；未支付时谎称已支付会被平台检出。订阅制按周/月/季收费（上限均 50 元），支持最低 5 次免费试用；完整 Skill 留在云端沙盒，本地 Agent 只能看到登录、提交与轮询模板，云端只回传本次任务所需的批改指引——实测中 Codex 全程看不到 SKILL.md 明文。平台当前不收服务费，支付通道「即刻收」抽 1%；上架需签两份协议并选经营类目，买断或订阅模式提交后不可更改，价格与试用额度可改。作者以「番茄小说拆文」Skill 做试验，第 6 次调用触发付费，同事侧即时到账。

### 4. Tracking Incidents of Hacking Using AI Tools
- **来源**: Schneier on Security · 2026-11-25
- **相关度**: 8/10 | 案例价值: HIGH
- **紧迫度**: next_version | 更新类型: new_evidence
- **目标章节**: Chapter 5, Section II
- **链接**: [https://www.schneier.com/blog/archives/2026/11/tracking-incidents-of-hacking-using-ai-tools.html](https://www.schneier.com/blog/archives/2026/11/tracking-incidents-of-hacking-using-ai-tools.html)
- **事件摘要**: 安全研究者 Daniel Miessler 建立两个互相链接的台账，Schneier 转发。hackingincidents.ai 收录 2023 年以来 286 起「攻击者使用 AI 或有可信证据表明使用」的网络攻击，每条按证据强度分为已确认、强证据、疑似，并标注所用模型、AI 承担的具体环节与信息来源。关键对比：2024 年 27 起已报告攻击中，没有一起描述由 AI 执行攻击；2026 年迄今 174 起中有 78 起是。offsecharnesses.ai 收录 154 个可在 GitHub 验证的开源攻击性 agent harness，其中仅 14 个出现在真实攻击中，涉及 26 个攻击组织，7 个与已确认的入侵事件相关。每条攻击记录都回链到厂商、事件响应公司、CERT 或政府报告。Miessler 自陈「肯定漏了一些，也弄错了一些」，接受更正。
- **理论关联**: 为 Chapter 5 的「能力扩散」提供第一份可审计的分母：从 0/27 到 78/174，变化不在工具供给（154 个 harness 早已公开），而在采用——14/154 说明扩散的瓶颈是意图而非能力。这与 11-25 亚马逊 0-day、11-26 EVIL 基准形成三角：模型越界率、真实攻击采用率、违法场景安全率，度量的是同一件事的不同切面。

- **紧迫度**: next_version | 更新类型: counter_argument

- **事件摘要**: OpenAI 的 Thariq Shihipar 在 AI Engineer CODE 的演讲，主张「革命」与「文艺复兴」两种未来可以并存：AI 让软件便宜到可以成千上万地生产，同时仍给人更多时间把一件事做到「对」。两个具体例子：他在自制格斗游戏的 /human 文件夹里改一块石头的大小，立刻试投掷，把手感当作唯一验收标准；他做了一个可切换模式的 Mac Dock，用完之后发现自己真正在意的不是效率，而是「注意到自己何时分心」。演讲还讨论决策模型如何从设计师定义的动作集合中选择，以及一个更政治化的问题：谁来决定哪些实验值得消耗算力。录制后他宣布加入 OpenAI。
- **理论关联**: 对「需求侧规训」提出反例而非否定：如果丰裕被用来买回打磨的时间，而不是买走摩擦，那么「叛逆」不必是重置目标函数，可以是重新分配省下的时间。但演讲自己留下了裂缝——「哪些实验值得算力」的决定权仍在少数人手里，丰裕的生产权与注意力的分配权并不在同一处。
